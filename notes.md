# Заметки по ходу решения

## Что требуется

1. Подсчёт токенов в агенте: для текущего запроса, для всей истории
   диалога, для ответа модели.
2. Сравнить короткий диалог, длинный диалог и диалог, который не влезает
   в контекст модели.
3. Показать рост токенов и стоимости по ходам и то, что ломается при
   переполнении.

## База

Задание 7 без правок: диалог с историей в JSON, два типа агентов, веб-интерфейс,
цикл хода в `internal/agent/runner.go`. Модуль переименован в `AITrenning_Task8`.

## Что известно про лимит

- `deepseek-v4-flash` и `deepseek-v4-pro`: контекст **1M токенов**, выход
  до 384K. Источник: <https://api-docs.deepseek.com/quick_start/pricing/>.
- Параметра, ограничивающего вход, в API **нет**. `max_tokens` режет только
  ответ. Переполнение видно только по ошибке в ответ на запрос.
- Официальный токенизатор — Python/HuggingFace
  (`deepseek_v4_tokenizer.zip`), для Go не годится. Документация даёт
  ориентиры: 1 английский символ ≈ 0.3 токена, 1 китайский ≈ 0.6. Про
  русский не сказано — коэффициент подбираем по факту из `usage`.

Отсюда решение: **свой мягкий лимит** `-context-limit` в агенте (для
воспроизводимых опытов на малых числах) плюс **одна настоящая проба** на
истории больше миллиона токенов, чтобы показать, что мягкий лимит
моделирует реальное поведение, а не выдумку.

## План

1. `internal/tokens` — оценка токенов до отправки: веса по классам символов,
   накладные на сообщение и на описание инструмента. Разбивка запроса на
   системный промпт, инструменты, историю и новое сообщение.
2. `Runner`: оценка перед каждым запросом к модели (внутри хода контекст
   растёт с каждым ответом инструмента), сверка оценки с фактом из `usage`,
   события журнала с обоими числами.
3. Мягкий лимит и поведение при переполнении: `fail` (по умолчанию),
   `trim` (выкидывать старые ходы), `off` (пусть отвечает API).
4. Интерфейс: разбивка токенов в панели промпта, факт против оценки под
   ответом, график роста по ходам.
5. Режим отчёта: короткий, длинный и переполненный диалог одной командой,
   таблица роста, сохранение в `examples/`.
6. Настоящая проба переполнения на синтетической истории > 1M токенов.
